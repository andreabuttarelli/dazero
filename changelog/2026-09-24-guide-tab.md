# A Guide tab next to Chat

The chat panel on the canvas gained a second tab, Guide, next to Chat — a small
in-product reference so a person doesn't need to leave the canvas to remember
what a wire does or how a loop combines.

## What's there

- `src/lib/shell-prefs.ts` gained `readChatTab`/`writeChatTab` (`dazero.chatTab`
  in localStorage), same try/catch pattern as every other shell pref in that
  file. Unknown value falls back to `chat`.
- `src/lib/components/canvas/CanvasChatPanel.svelte` grew a small tab bar
  (Chat | Guide) above the chat body. Switching tabs persists per viewer, same
  as the panel width.
- `src/lib/components/canvas/CanvasGuideTab.svelte`: a list of guide titles,
  click opens one rendered with `renderDocHtml` (the same sanitized markdown
  renderer as text nodes), a back link returns to the list.
- `src/lib/content/guides/`: five guides in Italian (app UI language), one file
  per guide (`*.guide.ts`), mirroring the changelog's one-file-per-entry
  pattern. `index.ts` globs and exposes them, `guideBySlug` for lookup.

## Guides written, and what they had to get right

Each guide was checked against the real code, not written from memory of the
spec:

- **Nodi e connessioni**: ports on a gen node come from the selected model's
  modalities (`connectorsFor` in `connectors.ts`), not from the node type —
  confirmed by reading `upstream-inputs.ts`'s own doc comment. Port colors
  taken from `CONNECTOR_STYLE`. A connected text node's generated output (or
  its prompt, if never run) becomes the downstream prompt — confirmed in
  `gen-history.ts`/`upstream-inputs.ts`.
- **Generare**: the history strip only shows landed runs —
  `gen-history.ts`'s `runs.filter((run) => run.mediaId !== null)`. Retry
  button label confirmed in `GenNode.svelte` (`Riprova`).
- **Loop**: read `loop-axes.ts`, `loop-plan.ts`, `loop.ts` directly. Combine
  mode is `product` (cartesian, default) or `zip` (index-paired, shortest
  wins) — both are real, distinct code paths (`cartesian`/`zipped` in
  `loop-plan.ts`), not something to guess. Confirm-above-50 /
  refuse-above-1000 are the literal constants `LOOP_CONFIRM_ABOVE`/`LOOP_MAX`.
  Wire-click-to-set-mode UI exists (`CanvasFlow.svelte`'s `retypeMode`, wired
  to `onEdgeModeChange`). The Loop button's `×N` label / hide-with-no-axis
  behavior is the concurrent `loopAffordance` work in `loop-axes.ts`
  (`visible = axes.length > 0 && combinationCount >= 2`) — read, not edited,
  by this change.
- **Selezione e scorciatoie**: every shortcut listed comes straight from
  `src/lib/canvas/shortcuts.ts`'s `matchCanvasShortcut` — nothing invented.
- **Creare un post**: the "in un post" marker is the `●` dot in
  `CanvasTile.svelte` (`title="Usato in un post"`), and the flow is
  `SelectionToolbar` → `CanvasFlow`'s `onCreatePost` → the `create-post` sheet
  entry → `CreatePostPage`. Kept the save/schedule description generic rather
  than quoting exact button labels I didn't find verbatim in the composer.

## Not done

`CanvasMobileTabs` was not touched. Its four entries (`MOBILE_TABS` in
`shell-nav.ts`) are each a full route or a fixed sheet id; the Guide tab lives
inside the chat panel, not as a fifth top-level destination, so adding it
there would be a different, unrequested feature (a route or sheet of its own)
rather than exposing what already exists.
